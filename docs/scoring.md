# 评分体系

## 为什么不用简单平均

一个页面 `noindex` 了，其它维度再完美它也搜不到。简单加权平均会给出"92 分但根本收录不了"这种荒谬结论。

所以用混合模型：

```
维度分 = Σ(规则权重 × 状态值) / Σ规则权重 × 100
状态值：pass=1，warn=0.45，fail=0

权重算术平均 A = Σ(维度分 × 维度权重)
权重几何平均 G = exp(Σ(维度权重 × ln(max(维度分, 0.5))))
总分 = 0.7A + 0.3G
```

几何平均对低分维度敏感：8 个维度里 7 个 95 分、1 个 20 分，算术平均是 85.6，几何平均只有 66.4，混合后 79.8——更接近真实感受。

## 硬性封顶

- 页面 `noindex`（meta 或 `X-Robots-Tag`）→ 总分封顶 35
- 返回 4xx/5xx → 通过 `http-status` 规则的 fail 大幅拉低对应维度

封顶的意义是：即使其它项全过，只要页面不可索引，结论就应该是"不合格"。

## 等级

| 分数 | 等级 | 含义 |
|---|---|---|
| ≥95 | A+ | 卓越 |
| ≥88 | A | 优秀 |
| ≥78 | B | 良好 |
| ≥65 | C | 及格 |
| ≥50 | D | 待改进 |
| <50 | F | 不合格 |

## 修复优先级

```
影响   = 严重度系数 × 规则权重 × 维度权重 × 当前损失比例 × 10
       严重度系数：critical=3，major=2，minor=1
       当前损失比例：fail=1，warn=0.45

工作量 = 人工标注（1=改一行，5=需要内容重构）

性价比 = 影响 ÷ 工作量
```

工作量是人工标注的，因为机器猜不准"给你加个 canonical"要 2 分钟还是 2 小时。几个例子：

| 规则 | 工作量 | 理由 |
|---|---|---|
| `title-length` | 1 | 改一行 HTML |
| `og-basic` | 2 | 加 4 个 meta 标签 |
| `structured-data` | 4 | 要设计 schema 结构 |
| `content-length` | 5 | 要重新写内容 |

## 预估收益

```
Δ维度分 = (规则权重 / 维度总权重) × 100 × 当前损失比例
Δ总分   = Δ维度分 × 维度权重
```

这是**近似值**：真实总分还受几何平均影响，改一条会同时影响 A 和 G。但量级是对的，足够用来排序。

报告里说"优先修这三项，预计提升约 7.5 分"，实测通常在 ±1.5 分内。

## 规则状态

| 状态 | 含义 | 计分 |
|---|---|---|
| `pass` | 通过 | 得满分 |
| `warn` | 有优化空间 | 得 45% |
| `fail` | 明确错误 | 0 分 |
| `info` | 仅提供信息，无法判定 | 不计入分母 |
| `skip` | 不适用（如无图片时的图片规则） | 不计入分母 |

`info` 和 `skip` 不参与计分很重要：一个没有图片的页面，不该因为"图片没有 alt"被扣分。

## 维度权重怎么定的

内容 22%、技术 18%、性能 16%、可发现性 14%、社交 10%、可访问性 10%、安全 5%、AI 可读性 5%。

依据是各因素对排名的实证影响程度：内容和可索引性是一票否决项，性能是门槛项，社交卡片影响点击率但不影响排名本身，安全是基础门槛（及格即可）。

AI 可读性给 5% 是因为它还在演进——给太高会让分数被新兴标准绑架，给 0 又忽视了趋势。
